# ESP-IDF 版本兼容

全部 13 个 ESP-IDF 示例面向 ESP32-S3，组件清单统一声明 `>=5.5.0,<6.3.0`。
用户手册优先使用 5.5 稳定版；6.2 当前使用固定 SDK 提交进行开发版兼容验证，
不将它标记为正式发行版，也不使用浮动的 `master` 构建。

## 验证环境

| 环境 | SDK 版本或提交 | 用途 |
| --- | --- | --- |
| 5.5 稳定版 | `v5.5.6`，`880a203ae603d08a94d06aa01e0d6761958e5e9e` | 示例 01–09 的稳定版 CI |
| 6.2 开发版 | `08e0d30a74ad0bfd5a34933142b80f45619ee410` | 示例 01–09 的实验性兼容 CI |
| 5.5 已有环境 | `v5.5.5` | 09 综合示例已完成编译与蓝牙队列主机回归 |

5.5.6 正式版见 [Espressif 发布页](https://github.com/espressif/esp-idf/releases/tag/v5.5.6)。
6.2 使用 [Espressif SDK 固定提交](https://github.com/espressif/esp-idf/commit/08e0d30a74ad0bfd5a34933142b80f45619ee410)。
两个 SDK 均支持本项目的 `esp32s3` 目标。其他目标芯片不在本项目验证范围内。

当前 CI 仅编译示例 01–09。LoRaWAN 示例 10–13 保留源码，需填写自己的
ID 和 Key 后本地编译，不参与自动编译及固件发布。下述历史验证结果仍保留。

## 09 综合示例

原来的 `>=6.2.0,<6.3.0` 依赖限制会在 IDF 5.5 下直接阻止配置。
综合示例使用的 PSA AES/SHA、唤醒接口和 NimBLE API 在验证环境中均可用，
无需切换到另一套应用实现。保留现有 Observer 模式蓝牙队列退出修复；
主机回归补充了 5.5 SDK 的互斥锁退出调用模拟，并在两个 CI 环境中运行。

本轮继续修复 GPIO ISR 重复安装、共享 SPI 重复初始化、RAM 自检分配与
AXP2602 温度处理，并移除持续压力测试；保留启动自检和无线、低功耗功能。
最终源码再次通过双版本编译和各 3 项 NimBLE 回归，源码契约与 RAM/ISR、
SPI/温度主机检查通过。当前行为详见 [09 README](../examples/esp-idf/09_comprehensive_demo/README.md)。

## 使用与切换版本

本仓库通过 `waveshare/waveshare_boards >=0.1.3` 自动下载
`esp32_s3_lr1121_epaper_2_9` 板型，无需手动复制。详细步骤见
[板型准备说明](../examples/esp-idf/README.md#board-manager-integration)。

在已加载对应 ESP-IDF 环境的 Ubuntu Bash 中进入所选示例目录：

```bash
python -m pip install esp-bmgr-assist==0.8.3
idf.py bmgr -l
idf.py bmgr -b esp32_s3_lr1121_epaper_2_9
idf.py set-target esp32s3
idf.py build
```

切换 SDK 时建议使用独立源码副本，重新生成板级配置和 `sdkconfig`，
避免沿用另一版本生成的配置。
生成目录、锁文件和编译产物均不提交到仓库。

## 验证边界

稳定版 CI 生成可发布固件；6.2 实验性任务单独报告编译结果，不参与稳定版
Release 的产物集合。全部示例要求 `waveshare/waveshare_boards >=0.1.3`，
该组件已包含产品板型；CI 在生成配置前检查下载组件中的板型文件。
历史本地构建记录不代表当前远端 Actions 已通过，远端结果应单独查看。
09 最终版本在 5.5.6 下应用分区余量为 22720 字节（约 1%），
6.2 下为 38608 字节（约 3%）；
增加功能时需要重新检查固件大小。
编译和主机测试不代表已完成蓝牙/Wi-Fi 共存、GPIO0 唤醒或整板休眠电流实测。
